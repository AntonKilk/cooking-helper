**Статус:** Draft v1

## 1. Обзор

Приложение-помощник по готовке для семьи в Финляндии. Решает проблему еженедельной рутины «что приготовить — что купить» через умный LLM-подбор рецептов и автоматическую генерацию списка покупок. Базовый сценарий: пользователь открывает приложение в начале недели, получает 3 рецепта с порциями, рассчитанными на 7 дней, и готовый список покупок, сгруппированный по категориям магазина.

## 2. Цели

- Сократить когнитивную нагрузку при планировании меню на неделю до 1–2 минут
- Дать персонализированный подбор, который улучшается со временем за счёт обратной связи
- Сгенерировать готовый shopping list, с которым можно идти в магазин без правок

## 3. Non-goals (MVP)

- Подсчёт нутриентов и калорий (Phase 2 — интеграция с nutridata.ee)
- Распознавание содержимого холодильника по фото
- Голосовой ассистент на кухне
- Интеграция с финскими магазинами (K-Ruoka, S-Kaupat, Foodora)
- Многопользовательский режим с авторизацией (но архитектура должна это допускать)
- Подсчёт стоимости продуктов

## 4. Целевой пользователь

**Primary:** Семья в Финляндии, готовят дома, хотят разнообразия и меньше времени на планирование.
**Контекст использования:** iPad на кухне (основная поверхность), также телефон в магазине.
**Языки UI:** RU / FI / EN (переключение в настройках, дефолт по системе).
**Профиль:** один «домашний» профиль на семью, без логина в MVP. Предпочтения хранятся локально + бэкап. Архитектура данных должна допускать миграцию на мультиюзер с авторизацией в будущем.

## 5. User Stories

1. Как пользователь, я хочу получить 3 рецепта на неделю одним нажатием, чтобы не тратить время на планирование.
2. Как пользователь, я хочу заменить любой из 3 рецептов, если он мне не нравится, без перегенерации остальных.
3. Как пользователь, я хочу полностью перегенерировать всю подборку, если ни один из вариантов не зашёл.
4. Как пользователь, я хочу видеть консолидированный список покупок, сгруппированный по категориям (овощи, мясо, молочное и т.д.), чтобы быстро пройти магазин.
5. Как пользователь, я хочу указать ингредиенты, которые я не люблю, чтобы они не попадали в подбор.
6. Как пользователь, я хочу лайкать/дизлайкать рецепты после готовки, чтобы система училась моим вкусам.
7. Как пользователь, я хочу, чтобы «базовые» продукты (соль, перец, масло, мука) не попадали в список покупок, потому что они всегда есть дома.
8. Как пользователь, я хочу видеть рецепт пошагово, удобно для чтения с iPad на кухне.
9. Как пользователь, я хочу переключить язык интерфейса между RU/FI/EN.

## 6. Функциональные требования (MVP)

### 6.1 Генерация недельного меню

- Кнопка «Сгенерировать неделю» → LLM возвращает 3 разных блюда.
- Порции каждого рецепта рассчитаны так, чтобы в сумме покрыть 7 дней еды (для семьи, размер семьи настраивается — дефолт 2 взрослых; параметризуется).
- Блюда не привязаны к конкретным дням — пользователь готовит когда хочет.
- LLM учитывает контекст: предыдущие подборки (избегать повторов), нелюбимые ингредиенты, фидбек, время года (опционально).
- Каждый рецепт включает: название, краткое описание, время готовки, порции, список ингредиентов с количествами, пошаговую инструкцию.

### 6.2 Swap / Regenerate

- На карточке каждого блюда — кнопка «Заменить» → перегенерация только этого рецепта с учётом, что 2 других остаются.
- Глобальная «Перегенерировать всё» — выбросить подборку и начать заново.

### 6.3 Shopping list

- Автогенерация из ингредиентов всех 3 рецептов.
- Консолидация дубликатов (250г + 100г моркови = 350г моркови).
- Группировка по категориям магазина: овощи и фрукты / мясо и рыба / молочное / бакалея / заморозка / прочее.
- Чекбоксы для отметки купленного.
- Базовая кладовая (соль, перец, растительное масло, сливочное масло, мука, сахар — редактируемый список) автоматически исключается из shopping list.
- Возможность вручную убрать любой пункт из списка.

### 6.4 Персонализация

- **Нелюбимые ингредиенты:** список в настройках, LLM получает в промпте, должен полностью исключать.
- **Базовая кладовая:** редактируемый список того, что всегда есть дома (для исключения из shopping list).
- **Обратная связь по рецептам:** после генерации/готовки рецепт можно лайкнуть / дизлайкнуть / отметить «приготовить снова». Фидбек сохраняется и подмешивается в промпт следующей генерации (n последних оценок + общий тон предпочтений).

### 6.5 Архив рецептов

- Все сгенерированные рецепты сохраняются локально.
- Просмотр истории, поиск по названию.
- Возможность «приготовить снова» из истории (добавит рецепт в текущую неделю).

### 6.6 Мультиязычность

- UI на RU / FI / EN, переключение в настройках.
- Рецепты генерируются на выбранном языке.
- Категории продуктов в shopping list переводятся.

## 7. Ключевые UX-флоу

### Флоу 1: Первый запуск
1. Выбор языка (или авто по системе)
2. Настройка размера семьи (взрослые / дети)
3. Опционально: указать нелюбимые ингредиенты
4. Опционально: подтвердить/отредактировать базовую кладовую (предзаполнено)
5. → Главный экран с кнопкой «Сгенерировать неделю»

### Флоу 2: Еженедельная генерация
1. Кнопка «Сгенерировать неделю»
2. Лоадер на 5–15 секунд
3. Экран с 3 карточками рецептов (название, фото/иконка, время, краткое описание)
4. Кнопки: «Список покупок» / «Заменить» на каждой / «Перегенерировать всё»

### Флоу 3: Готовка
1. Тап на карточку рецепта
2. Полноэкранный режим: ингредиенты + шаги (крупный шрифт, удобно с iPad на кухне)
3. После готовки — лайк / дизлайк / «приготовить снова»

### Флоу 4: Магазин
1. Открыть shopping list
2. Видеть группы по категориям
3. Отмечать купленное чекбоксом

## 8. Высокоуровневая модель данных

```
HouseholdProfile
  - id (для будущей миграции на мультиюзер)
  - language: ru | fi | en
  - family_size: { adults, kids }
  - disliked_ingredients: string[]
  - pantry_basics: string[]

Recipe
  - id, created_at
  - title, description
  - language
  - cook_time_minutes
  - servings
  - ingredients: [{ name, amount, unit, category }]
  - steps: string[]
  - source: 'llm' | 'history'
  - feedback: { liked, disliked, cook_again, created_at }

WeeklyPlan
  - id, week_start
  - recipe_ids: [id, id, id]
  - shopping_list: [{ name, amount, unit, category, checked, manually_removed }]
```

## 9. Phase 2 (после MVP)

В порядке приоритета, по интересу автора:

1. **Интеграция с nutridata.ee** — глубокое погружение в эстонскую базу нутриентов; подсчёт КБЖУ и нутриентного баланса недели. Рабочий проект автора.
2. **Поиск рецептов по холодильнику** — ввод/фото имеющихся продуктов, подбор рецепта.
3. **Голосовой ассистент** — диалог во время готовки («что дальше?», «повтори шаг»).
4. **Интеграция с финскими магазинами** — экспорт shopping list в K-Ruoka, S-Kaupat, Foodora.
5. **Мультиюзер с авторизацией** — несколько профилей в семье, индивидуальные предпочтения и аллергии.

## 10. Открытые вопросы (для tech design)

- **Платформа:** PWA (быстрее запустить, iPad через Safari) vs native iOS (нужно для Phase 2 — камера/микрофон). Решение в tech design.
- **LLM-провайдер:** Claude (Anthropic API) — наиболее вероятный выбор. Возможна провайдер-агностичная архитектура. Решение в tech design.
- **Хранение данных:** локально (SQLite/IndexedDB) vs облако с нуля. Влияет на лёгкость миграции на мультиюзер.
- **Изображения рецептов:** генерация AI / стоковые / без картинок? Влияет на cost и UX.
- **Алгоритм расчёта порций на 7 дней:** как именно LLM делит еду — 3 блюда × N порций, где сумма = 7 × размер семьи? Нужен чёткий промпт-контракт.

## 11. Метрики успеха

- Время от открытия приложения до готового shopping list: < 2 минут
- Доля недель, где пользователь использовал ≥ 1 рецепт без замены: > 60%
- Процент рецептов с положительным фидбеком после готовки: > 70% (через 4 недели использования)
- Retention: пользователь возвращается генерировать новую неделю ≥ 3 недели подряд
