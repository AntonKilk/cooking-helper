## 1. Executive Summary

Cooking Helper — приложение-помощник по планированию еженедельного домашнего меню для семьи в Финляндии. Решает проблему когнитивной нагрузки «что приготовить на неделю и что купить», заменяя ручное планирование на умный LLM-подбор с учётом персональных вкусов, нелюбимых ингредиентов и истории обратной связи.

Основной сценарий MVP: в начале недели пользователь нажимает «Сгенерировать неделю», получает 3 разных рецепта с порциями, рассчитанными на 7 дней еды, и автоматически сгенерированный список покупок, сгруппированный по категориям магазина. Готовку и фидбек ведёт через тот же интерфейс, преимущественно с iPad на кухне.

**MVP goal:** Сократить время недельного планирования меню до < 2 минут при сохранении разнообразия и персонализации подбора.

## 2. Mission

Дать семье инструмент, который снимает рутину планирования еды и постепенно учится их вкусам, не требуя от пользователя ведения сложных баз данных или ручной разметки.

**Core principles:**
- **Простота над функциональностью** — один тап, чтобы получить план недели
- **Персонализация через фидбек** — система улучшается от использования, а не от настроек
- **Кухонный UX** — оптимизация под iPad, крупные шрифты, минимум нажатий
- **Мультиязычность с рождения** — RU / FI / EN не доработка, а базовое требование
- **Архитектура под будущий рост** — MVP однопользовательский, но данные структурированы под мультиюзер

## 3. Target Users

**Primary persona — Семейный повар:**
- Семья в Финляндии (2 взрослых + опционально дети)
- Готовит дома 3+ раза в неделю
- Хочет разнообразия, но устал планировать
- Технически комфортен с приложениями уровня «потребитель» (Spotify, Netflix), но не разработчик
- Использует iPad на кухне, телефон в магазине

**Pain points:**
- Каждую неделю одинаковые блюда из-за усталости от планирования
- Забывает купить ингредиенты, идёт в магазин 2-3 раза
- Cookbook/Pinterest рецепты не учитывают, что уже есть дома
- Существующие приложения для планирования меню требуют ручного ведения списков и не персонализируются

**Key needs:**
- Быстрая генерация плана недели (< 2 минут)
- Готовый shopping list без правок
- Учёт «не люблю петрушку» без повторного указания каждую неделю
- Поддержка финских реалий (доступность продуктов, привычные категории магазина)

## 4. MVP Scope

### In Scope

**Core Functionality:**
- [ ] Генерация недельного меню из 3 разных рецептов с порциями на 7 дней еды
- [ ] Замена одного рецепта без перегенерации остальных (swap)
- [ ] Полная перегенерация всей подборки (regenerate all)
- [ ] Просмотр рецепта в полноэкранном режиме (ингредиенты + пошагово)
- [ ] Автогенерация консолидированного shopping list из 3 рецептов
- [ ] Группировка shopping list по категориям магазина (овощи, мясо, молочное, бакалея, заморозка, прочее)
- [ ] Чекбоксы для отметки купленного в shopping list
- [ ] Возможность вручную убрать пункт из shopping list

**Персонализация:**
- [ ] Список нелюбимых ингредиентов (исключаются из подбора)
- [ ] Базовая кладовая — редактируемый список «всегда есть дома» (исключается из shopping list)
- [ ] Лайк / дизлайк / «приготовить снова» на каждый рецепт после готовки
- [ ] Передача n последних оценок в промпт следующей генерации

**Архив:**
- [ ] Локальное сохранение всех сгенерированных рецептов
- [ ] Поиск по названию в архиве
- [ ] Действие «приготовить снова» из архива (добавляет в текущую неделю)

**Конфигурация семьи:**
- [ ] Настройка размера семьи (взрослые / дети)
- [ ] Выбор языка UI (RU / FI / EN) с автоопределением по системе
- [ ] Генерация рецептов на выбранном языке

**iPad UX:**
- [ ] Адаптивная вёрстка с приоритетом iPad
- [ ] Крупный шрифт и достаточная контрастность в режиме «готовлю»

### Out of Scope (Phase 2+)

**Питание и нутриенты:**
- [ ] Интеграция с nutridata.ee, подсчёт КБЖУ
- [ ] Контроль баланса нутриентов недели
- [ ] Учёт аллергий с медицинской точки зрения

**AI-расширения:**
- [ ] Распознавание содержимого холодильника по фото
- [ ] Голосовой ассистент во время готовки
- [ ] Адаптация к сезону / погоде / праздникам автоматически

**Магазины и стоимость:**
- [ ] Интеграция с K-Ruoka, S-Kaupat, Foodora
- [ ] Подсчёт стоимости покупок
- [ ] Сравнение цен между магазинами

**Multi-user:**
- [ ] Авторизация и индивидуальные профили внутри семьи
- [ ] Облачная синхронизация между устройствами
- [ ] Шеринг рецептов между семьями

## 5. User Stories

**US-1: Быстрая генерация недели**
> Как пользователь, я хочу получить план недели одним нажатием, чтобы не тратить время на ручное планирование.
>
> *Пример:* Вс вечером открываю приложение, тапаю «Сгенерировать неделю», через 15 секунд вижу 3 рецепта.

**US-2: Точечная замена рецепта**
> Как пользователь, я хочу заменить один из 3 рецептов, если он мне не нравится, не теряя остальные.
>
> *Пример:* Получил «лосось с укропом», но недавно ел лосось. Тапаю «Заменить» — остальные 2 рецепта остаются, заменяется только этот.

**US-3: Полная перегенерация**
> Как пользователь, я хочу перегенерировать всю подборку, если ни один рецепт не зашёл.
>
> *Пример:* Все 3 рецепта — супы, а хотелось второго. Тапаю «Перегенерировать всё».

**US-4: Удобный shopping list**
> Как пользователь, я хочу видеть список покупок, сгруппированный по отделам магазина, чтобы быстро пройти магазин.
>
> *Пример:* В магазине открываю shopping list, вижу секции «Овощи», «Мясо», «Молочное» — иду по магазину сверху вниз, отмечаю чекбоксами.

**US-5: Исключение нелюбимых ингредиентов**
> Как пользователь, я хочу указать ингредиенты, которые я не люблю, чтобы они никогда не попадали в подбор.
>
> *Пример:* Добавляю «кинза», «оливки» в список disliked — следующие генерации их избегают.

**US-6: Обратная связь по рецептам**
> Как пользователь, я хочу лайкать/дизлайкать рецепты после готовки, чтобы система училась моим вкусам.
>
> *Пример:* После ужина тапаю на карточку, ставлю лайк и «приготовить снова». На следующей неделе видны похожие по стилю блюда.

**US-7: Базовая кладовая**
> Как пользователь, я хочу, чтобы соль, перец, масло не попадали в shopping list, потому что они всегда есть дома.
>
> *Пример:* В рецепте 5г соли — в shopping list соли нет. В настройках могу добавить «оливковое масло» в кладовую.

**US-8: Удобство iPad на кухне**
> Как пользователь, я хочу видеть рецепт крупным шрифтом во время готовки, чтобы читать его с iPad на столе.
>
> *Пример:* Открываю рецепт в полноэкранном режиме, текст крупный, можно скроллить шаги одной рукой в перчатке.

**US-9: Переключение языка**
> Как пользователь, я хочу переключить язык UI и рецептов между RU/FI/EN.
>
> *Пример:* Жена говорит по-фински — переключает в FI и читает рецепт на финском с финскими названиями ингредиентов.

## 6. Core Architecture & Patterns

> **Note:** Детальная архитектура и стек определяются в отдельном tech design документе. Здесь — высокоуровневые принципы.

**Архитектурные принципы:**
- **Home-network-first данные** (с возможностью миграции на cloud) — данные централизованно хранятся на домашнем сервере в SQLite, iPad — клиент в домашней сети через Tailscale Serve; iPad вне домашней сети не работает (accepted trade-off); миграция на cloud — будущая фича
- **LLM как core engine** — генерация меню, рецептов, парсинг ингредиентов в категории происходит через LLM-вызовы; промпты — версионируемый артефакт
- **Provider-agnostic LLM-слой** — абстракция, позволяющая в будущем подключить разные модели (по умолчанию Claude)
- **i18n с первого коммита** — все строки UI через систему переводов, никаких хардкодов
- **Household profile как корневая сущность** — данные группируются вокруг профиля семьи; в будущем профилей будет несколько

**Высокоуровневые компоненты:**
- UI Layer (iPad-first, адаптивно)
- Local Storage (профиль, архив, недельные планы, фидбек)
- LLM Service (промпты, парсинг ответов, retry)
- i18n Service (RU/FI/EN)
- Shopping List Builder (консолидация ингредиентов, маппинг в категории)

## 7. Tools / Features

### F-1: Weekly Menu Generator
- **Назначение:** Сгенерировать 3 разных блюда на неделю
- **Входы:** household profile, disliked ingredients, n последних feedback записей, история n последних недель (для избегания повторов)
- **Выходы:** 3 объекта Recipe с порциями, суммарно покрывающими 7 дней × размер семьи
- **Ключевые требования:**
  - Время генерации < 30 секунд
  - Минимум 2 категории белка между 3 рецептами (разнообразие)
  - Уважение dislikes — 100% исключение

### F-2: Recipe Swap / Regenerate
- **Назначение:** Замена 1 или всех 3 рецептов
- **Входы:** текущая подборка (для swap — 2 «оставленных», для regen all — пустой контекст)
- **Выходы:** новый Recipe / новая тройка
- **Особенности:** swap должен учитывать оставшиеся 2 рецепта чтобы не дублировать профиль блюда

### F-3: Shopping List Builder
- **Назначение:** Собрать единый список покупок из 3 рецептов
- **Входы:** ингредиенты 3 рецептов, pantry_basics, manually_removed items
- **Выходы:** консолидированный список с группировкой по категориям
- **Логика консолидации:** одинаковые ингредиенты суммируются по количеству с приведением единиц (250г + 100г моркови = 350г)
- **Pantry exclusion:** ингредиенты из pantry_basics не попадают в список

### F-4: Recipe Detail View
- **Назначение:** Просмотр рецепта во время готовки
- **Особенности iPad UX:** крупный шрифт (минимум 18pt body), высокая контрастность, шаги в карусели или вертикальном списке с активным шагом

### F-5: Feedback Collection
- **Назначение:** Собрать оценку рецепта после готовки
- **Состояния:** liked / disliked / cook_again (булевы независимые)
- **Использование:** последние n записей подмешиваются в промпт следующей генерации

### F-6: Pantry Basics Management
- **Назначение:** Редактирование списка «всегда есть дома»
- **Дефолт:** соль, чёрный перец, растительное масло, сливочное масло, мука пшеничная, сахар
- **Действия:** добавить / удалить ингредиент

### F-7: Disliked Ingredients Management
- **Назначение:** Управление списком исключений
- **Действия:** добавить / удалить
- **Использование:** передаётся в промпт каждой генерации как hard constraint

### F-8: Recipe Archive
- **Назначение:** Доступ к ранее сгенерированным рецептам
- **Действия:** поиск по названию, «приготовить снова» (добавляет в текущую неделю)

### F-9: i18n Switcher
- **Назначение:** Переключение языка UI и рецептов
- **Языки:** RU / FI / EN
- **Поведение:** при смене языка следующая генерация — на новом языке; ранее сгенерированные рецепты остаются на языке их создания

## 8. Technology Stack

> **Status:** Locked-in. Полное обоснование и альтернативы — в [`.agents/tech-design.md`](../tech-design.md).

**Финальный стек:**

| Слой | Решение |
|---|---|
| Архитектура | Home-network-first (см. §6) |
| Backend | Go + `html/template` + HTMX (SSR) |
| Database | SQLite в Docker volume |
| Hosting | Docker на Mac mini Intel i7 |
| Network / TLS | Tailscale Serve (только tailnet) |
| LLM | Anthropic Go SDK, Sonnet 4.6 + Haiku 4.5 через `internal/llm` |
| i18n | JSON-словари + `t()` в шаблонах |
| Клиент | PWA на iPad с Service Worker |
| UI generation (dev-time) | Anthropic `frontend-design` skill, HTML/CSS only, Nordic Kitchen design system |
| Изображения рецептов | Нет в MVP, emoji + типографика |
| Экспорт shopping list | Apple Reminders через Shortcuts x-callback-url (Phase 2) |

**Constraints, которые остаются valid:**
- iPad Safari как primary target
- Offline-режим для уже сгенерированных рецептов (через Service Worker)
- Модели данных с `household_id` под будущий multi-user

## 9. Security & Configuration

**MVP (single household, no auth):**
- Нет авторизации, нет аккаунтов
- Данные хранятся локально на устройстве
- LLM API ключ — на сервере в env-переменной (`ANTHROPIC_API_KEY`), никогда не в коде, никогда на клиенте
- Никаких персональных данных пользователя не отправляется в LLM, кроме: preferences (dislikes, pantry), feedback по рецептам, история генераций

**Конфигурация:**
- Environment-зависимые переменные (LLM endpoint, API key) — через стандартный механизм окружения выбранной платформы
- Промпты — версионируются в репозитории, не в env

**Out of scope в MVP:**
- Авторизация и identity management
- Шифрование пользовательских данных на устройстве
- Audit log

## 11. Success Criteria

**MVP success определяется как:**
Пользователь использует приложение ≥ 3 недели подряд для генерации меню и доводит ≥ 1 рецепт в неделю до готовки с положительным фидбеком.

**Functional requirements:**
- [ ] Генерация недели за ≤ 30 секунд
- [ ] Shopping list группируется по категориям без ручной разметки
- [ ] Disliked ingredients никогда не появляются в подборе (100% соблюдение)
- [ ] Pantry basics никогда не появляются в shopping list (100% соблюдение)
- [ ] UI работает на iPad Safari без визуальных артефактов
- [ ] Все строки UI доступны на RU/FI/EN

**Quality indicators:**
- Время от открытия приложения до готового shopping list: < 2 минут
- Доля недель, где пользователь использовал ≥ 1 рецепт без замены: > 60%
- Процент рецептов с положительным feedback после готовки: > 70% (через 4 недели использования)
- Retention: возврат для генерации новой недели ≥ 3 недели подряд

**UX goals:**
- Главная задача — сгенерировать неделю — выполняется в ≤ 2 тапа
- Просмотр рецепта во время готовки не требует масштабирования на iPad
- Shopping list используется без правок в > 80% случаев

## 12. Implementation Phases

### Phase 1: Foundation (Week 1-2)
**Goal:** Минимальный скелет приложения с локальным хранением и i18n

**Deliverables:**
- [ ] Tech design document подписан
- [ ] Скелет проекта с выбранным стеком
- [ ] Локальное хранилище: модели HouseholdProfile, Recipe, WeeklyPlan
- [ ] i18n каркас с RU/FI/EN, переключатель в настройках
- [ ] Базовая навигация: главный экран, настройки, рецепт

**Validation:**
- Запускается на iPad Safari
- Переключение языка работает
- Профиль семьи можно создать и сохранить локально

### Phase 2: LLM Integration & Core Generation (Week 3-4)
**Goal:** Работающая генерация недели через LLM

**Deliverables:**
- [ ] LLM service с retry-логикой и парсингом JSON
- [ ] Промпт генерации недели (3 рецепта × порции на 7 дней)
- [ ] Учёт disliked ingredients и pantry в промпте
- [ ] Промпт замены одного рецепта
- [ ] Экран с 3 карточками рецептов
- [ ] Полноэкранный просмотр рецепта

**Validation:**
- 10 тестовых генераций дают разнообразные блюда
- Disliked игнорируется в 100% тестов
- Полноэкранный режим читается с iPad с расстояния 50см

### Phase 3: Shopping List & Personalization (Week 5-6)
**Goal:** Полный цикл «генерация → готовка → фидбек → улучшение»

**Deliverables:**
- [ ] Shopping list builder с консолидацией и категоризацией
- [ ] Pantry basics CRUD
- [ ] Disliked ingredients CRUD
- [ ] Feedback на рецепты (лайк/дизлайк/cook again)
- [ ] Использование feedback в промпте следующей генерации
- [ ] Архив рецептов + поиск + «приготовить снова»

**Validation:**
- Shopping list корректен на 5 тестовых меню
- Feedback заметно влияет на стиль следующих подборок (subjective check)

### Phase 4: Polish & Beta (Week 7-8)
**Goal:** Готовый MVP, используемый своей семьёй

**Deliverables:**
- [ ] Пользовательское тестирование на iPad на кухне
- [ ] Багфиксы по итогам тестов
- [ ] Финальная вёрстка iPad / mobile
- [ ] Базовый onboarding для первого запуска
- [ ] README и инструкция для бета-пользователей

**Validation:**
- Семья автора использует MVP 2 недели подряд без вмешательства разработчика
- Метрика «время до shopping list» подтверждена < 2 минут

## 13. Future Considerations

**Phase 2 фичи в порядке приоритета:**

1. **Интеграция с nutridata.ee** — подсчёт КБЖУ и нутриентного баланса недели. Глубокое погружение в эстонскую базу нутриентов (рабочий проект автора).
2. **Поиск рецептов по содержимому холодильника** — ручной ввод или фото имеющихся продуктов, подбор рецепта.
3. **Голосовой ассистент** — диалог во время готовки («что дальше?», «повтори шаг»).
4. **Интеграция с финскими магазинами** — экспорт shopping list в K-Ruoka, S-Kaupat, Foodora.
5. **Multi-user с авторизацией** — несколько профилей в семье, индивидуальные предпочтения и аллергии, облачная синхронизация.

**Возможные расширения дальше:**
- Сезонные рекомендации (учёт времени года, праздников)
- Импорт рецептов извне (ссылка → разбор → сохранение)
- Социальная фича: шеринг недели с друзьями
- Apple Watch / iPhone widget с напоминанием «что готовим сегодня»

## 14. Risks & Mitigations

| Риск | Влияние | Митигация |
|---|---|---|
| **LLM генерирует невыполнимые / странные рецепты** (несовместимые ингредиенты, нелогичные шаги) | Высокое — подрывает доверие | Промпт с явными требованиями к практичности; валидация JSON-схемы; кнопка «сообщить о проблеме» с обратной связью в улучшение промпта |
| **Стоимость LLM-вызовов превышает бюджет личного использования** | Среднее — может остановить разработку | Кэширование промежуточных результатов; использование меньших моделей где возможно; мониторинг расхода токенов с самого начала |
| **Disliked ingredients игнорируются LLM** в редких случаях | Высокое — теряется доверие | Post-processing валидация: после ответа LLM сравниваем ингредиенты со списком disliked и регенерируем при нарушении |
| **iPad Safari ограничения** (storage limits, PWA quirks) выявятся поздно | Среднее — может потребовать переход на native | Раннее тестирование на реальном iPad в Phase 1; запас на миграцию заложен в архитектуре |
| **Локализация рецептов на финский** даёт калькированные/неестественные тексты | Среднее — раздражает носителей | Промпт с примерами стиля для каждого языка; ручной review первых 20 рецептов на FI с носителем |
| **Архитектура local-first усложнит миграцию на multi-user** | Низкое-среднее — отдалённое | Модели данных с самого начала с household_id; абстракция storage layer для замены на cloud |
